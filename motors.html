Chapter 5 · Hands-on

Give every motor an ID

Before the motors are screwed into the arm, each one needs its own number. You do this first because it must be done one motor at a time, which is far easier while they are loose on the table.

30 minutesYou need: labelled motors, both control boards, power supplies, USB cables, computer with LeRobot installed
Pre-assembled kit?

The vendor has usually done this for you. Read the chapter to understand it, do only "Find the port" below, then continue to calibration.

Why this step exists

In chapter 2 you saw that all six motors of an arm share one set of wires (a bus), and that the computer addresses each by its ID. New motors leave the factory all set to ID 1. If you chained six of them together now, a message to "ID 1" would be answered by all six at once and the replies would collide into garbage.

So you connect one motor alone, tell it "your ID is now 6", then the next alone, "you are 5", and so on. The motor stores its ID in permanent memory (EEPROM), so it remembers after the power is off. You only ever do this once per motor.

The same command also sets the baud rate: the speed, in bits per second, at which the motors and computer exchange data. LeRobot uses 1,000,000 bits per second. Both sides must use the same speed, like two people agreeing how fast to speak.

Part A: find the port

When you plug a control board into USB, your computer gives the connection a name called a port. You need that name for every command from now on.

  1. Connect one board

    Take the follower's control board. Plug its power supply into the wall and into the board, and connect the board to your computer with a USB-C cable. No motors need to be attached yet.

    Waveshare boards only

    If your board has two tiny jumper caps next to labels A and B, both must be on B. B means "controlled over USB".

  2. Run the port finder

    Open your terminal, activate your environment (conda activate lerobot, see chapter 4) and run:

    lerobot-find-port

    It lists the ports it can see, then asks you to unplug the USB cable and press Enter.

  3. Unplug, press Enter, read the answer

    Unplug the USB cable from the board, then press Enter. The program prints the port that disappeared:

    The port of this MotorsBus is 'COM5'
Reconnect the USB cable.

    On Windows the name is COM plus a number. Your number will differ. You can also see it in Device Manager under "Ports (COM & LPT)".

    The port of this MotorsBus is '/dev/tty.usbmodem575E0032081'
Reconnect the USB cable.
    The port of this MotorsBus is '/dev/ttyACM0'
Reconnect the USB cable.

    On Linux you may also need to give yourself permission to use the port:

    sudo chmod 666 /dev/ttyACM0

    Write the port name on a sticky note and put it on the follower's board. Plug the USB cable back in.

  4. Repeat for the leader's board

    Do the same with the leader's board and its own (5V) power supply, and note its port too.

Why the unplugging trick?

Your computer may have several serial devices, and nothing on the board announces "I am the follower". The program takes a list of ports, waits for you to unplug, takes the list again, and reports whichever name vanished. Simple and reliable. Port names can change when you use a different USB socket or restart, so if a later command cannot find the arm, run lerobot-find-port again.

Part B: set the IDs of the follower's motors

  1. Start the setup program

    Have your six motors labelled F1–F6 ready. Use the follower's port in place of the example:

    lerobot-setup-motors --robot.type=so101_follower --robot.port=COM5
    lerobot-setup-motors \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem575E0032081
    lerobot-setup-motors \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0
    lerobot-setup-motors --robot.type=so101_follower --robot.port=…

    The backslash \ at the end of a line on macOS and Linux only means "the command continues on the next line". On Windows the whole command is written on one line.

  2. Connect only the gripper motor

    The program says:

    Connect the controller board to the 'gripper' motor only and press enter.

    Plug a 3-wire cable from the board to motor F6, and nothing else. Check the power plug has not worked loose (it often does while you handle the board), then press Enter.

    'gripper' motor id set to 6

  3. Swap to the next motor, five more times

    Unplug the cable from the board (you can leave it in the motor, it will be needed there later). Connect the next motor the program asks for, alone, and press Enter. The order counts down from the hand to the base:

    Program asks forConnect your motorID it receives
    gripperF66
    wrist_rollF55
    wrist_flexF44
    elbow_flexF33
    shoulder_liftF22
    shoulder_panF11

    When the sixth is done the program simply ends. That means success.

Part C: the leader's motors

Switch to the leader's board, its 5V power supply and its port. The command is almost the same, but because the leader is a "teleoperator" and not a "robot", the option names change:

lerobot-setup-motors --teleop.type=so101_leader --teleop.port=COM6
lerobot-setup-motors \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem575E0031751
lerobot-setup-motors \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1

Here the labels matter most. When it asks for gripper connect L6, for wrist_roll connect L5, and so on down to L1. Because the leader's motors have different gears, a motor given the wrong ID will end up in the wrong joint.
